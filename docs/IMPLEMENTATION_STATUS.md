# Implementation Status

Last updated: 2026-10-27. This file describes the current release candidate; preserve the compact-only shell and do not reset, clean, or reinitialize submodules. Manual checks remain listed below.

## Completed

- **Single compact window.** `MainWindow` is the only product window: 430 x 660 with custom compact chrome, manual title-bar drag, vector pin/settings/minimize/close controls and no maximize or resize. Windows 11 supplies rounded DWM corners; Windows 10 may fall back to square corners. The title bar shows the circular SonaBar mark, wordmark, a local/private pill and a session-only always-on-top pin. It shows the current state, mode, shortcut, model, effective processing path, last transcription with copy and one start/stop action. The old 1080 x 780 workspace and `CompactWindow` are gone. All 20 pages are reached from the **Go to** selector; the header gear opens `SettingsDialog`. Closing the window keeps SonaBar in the tray, and **Tray > Tools** offers Home, History, Transcribe File, Meeting Mode and All settings.
- **Public source link in About.** The About page exposes a `Source code on GitHub` button that opens `https://github.com/silasnetwin/SonaBar`. The README is refreshed for the public repository with download, privacy, build and verification information.
- **Compact settings and onboarding handoff.** `SettingsDialog` covers mode, shortcut capture, minimum hold, installed model or automatic profile, language, processing device and Whisper CPU threads. Writing models, custom words, snippets, applications, history and diagnostics remain on their pages through **Go to**. Finishing Welcome raises `MainWindow.OnboardingCompleted`, which shows the compact window instead of leaving the app tray-only until the next launch.
- **Compact-only focus and layout polish.** The 430 x 660 window (414 x 621 client area) fits without a scrollbar in the measured Home and settings layouts. Home has no second Settings button; the header gear is the settings entry. The read-only transcription box is skipped in the tab order. WPF's dotted focus rectangle is replaced by a solid accent border or a soft icon highlight; keyboard focus remains visible without the dashed box.
- **Settings schema 5 and honest processing controls.** `ProcessingDevice` (`Automatic`, `Cpu`, `Gpu`) replaces the legacy `Backend` field; `CpuThreads` (0 = automatic) and `MinHoldMs` (0-2000 ms) are validated and clamped. Schema 4 `Backend` values migrate without losing the user's choice. Whisper can use an explicit CPU thread count, reports GPU-to-CPU fallback, and reloads after a device change. The router forwards the fallback notice, and the compact/Advanced summaries change to `GPU unavailable (CPU fallback)`. Parakeet and Qwen are CPU-only and show that their runtimes manage their own threads.
- **Push-to-talk minimum hold.** A release before the configured threshold discards the recording and reports the required hold time. The key-up timestamp is captured immediately, so a slow microphone or model start cannot turn a short accidental press into a valid hold. The threshold is off by default.
- **Parakeet speech-context plumbing, no boosting claim.** Custom words are deduplicated, trimmed and capped at 64, then passed to NeMo-Speech.cpp as one native speech-context request. The native TDT head logs that it ignores speech contexts without a Flashlight decoder, so the app and docs do not claim a Parakeet accuracy gain; Whisper and local writing still use the words. A `--hotword=country` native smoke exercised the ABI path and confirmed the runtime message.
- **Compact action correctness.** The Home primary button stops and inserts while recording, cancels during startup or later processing, shows **Preparing...** while the model is checked, and routes a missing-model state to Models.
- **Silent second launch.** Starting the installed app again now signals the existing instance and exits without a blocking message box, which brings the compact window back from the tray. The "already running" warning remains only when the existing process is a different executable path. `ShouldWarnAboutOtherInstance` has four focused tests.
- Rebranded application, WPF shell, assets, installer, documentation, and release output as **SonaBar by SilasNet**.
- Added the in-app **About → Help** page with quick start, delivery troubleshooting, privacy, diagnostics and free-software guidance. The page smoke test renders all 20 pages without failures.
- Confirmed the free product policy: no checkout, subscription, trial timer, licence server or fake purchase UI.
- Added optional feedback sounds with original generated WAV cues. **Off** remains the default; **Minimal** plays the finished tone; **Standard** adds start and error tones. Playback is best-effort and cannot fail a dictation. The Audio page previews the finished tone and disables preview while sounds are off.
- Added opt-in typed snippet expansion. `TypedSnippetMatcher` enforces case-insensitive word-boundary matches, ignores one-character and control-character triggers, rejects surrogate pairs and combining marks because Backspace may count graphemes rather than UTF-16 code units, and prefers the longest alternative. The global keyboard hook buffers ordinary keystrokes, including spaces and punctuation inside multi-word triggers, ignores injected input, skips SonaBar and password fields, suppresses the completing delimiter, removes the trigger and inserts the expanded content with `{date}`, `{time}` and `{clipboard}` variables. A low-level mouse hook clears the buffer when the caret may have moved; Enter and Tab without a match also reset it. It is off by default and warns about games and elevated targets.

- **Fixed the settings file.** A hand edited `settings.json` with a readable enum name used to reset the whole configuration; enums are now written as names and read in both forms.
- **Fixed the endless "Getting ready" state and the long start.** Target capture now runs on a dedicated STA thread with a hard timeout, a field inside SonaBar is inspected on the interface thread, the window appears before any engine work, and a missing model is an explicit state instead of a silent 465 MB download. See `docs/STARTUP_AND_FRAME_2026-10-22.md`.
- **Moved to compact custom chrome and one colour system.** `ThemedWindow.UseCompactChrome()` uses `WindowStyle=None` with a zero-caption/zero-resize `WindowChrome`, manual title-bar drag, vector pin/settings/minimize/close controls and DWM rounded corners. Every colour stays in `src/SonaBar.App/Palette.cs` (light by default for new installations).
- **Startup registration is applied at initialization.** `AppController.Initialize()` now synchronizes the per-user `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\SonaBar` value from `LaunchAtLogin` on every normal start, so a fresh installer launch creates the tray startup entry without requiring a settings save. A registry failure is logged and does not block startup.
- **Opaque game windows are captured without UI Automation.** Target capture no longer rejects a foreground window that exposes no `AutomationElement`; the explicit **Compatibility** profile pastes into the verified window and reports the exact status. Normal fields still fail before recording when Windows cannot inspect them, and selection editing still requires an editable field.
- **The Start button returns to the last external app.** A foreground tracker remembers the last non-SonaBar window, and dictation or selection capture restores it when SonaBar itself is foreground. Starting from the app window therefore no longer targets the app's own button.
- **Browser contenteditables are found inside the target window.** Target discovery searches the foreground window's own UI Automation tree for the focused `Edit` or `Document` instead of trusting `AutomationElement.FocusedElement`, which can return a stale element from another process. Chrome/Claude contenteditables now produce a normal `Edit` target, and a delayed `ValuePattern` update no longer causes a duplicate SendInput pass.
- **Foreground restore is retried through the foreground and target threads.** `Native.ForceForegroundWindow` attaches to both threads, restores and raises the target, falls back to `SwitchToThisWindow`, and only restores a minimized target instead of unmaximizing an intentionally maximized one. A browser, editor or game behind SonaBar or its overlay no longer fails with "Windows prevented restoring focus."
- **Stale UI Automation selections no longer fail a dictation.** A selection captured before a long transcription can expire while the target field is still healthy. `TextInsertion` now logs the stale selection, reacquires the focused editable node, retries `SetFocus` and foreground activation, and continues at the current caret. Replacement paths still validate the original passage and refuse an unsafe edit. Diagnostics distinguish `selection_restore_failed`, `selection_reacquired` and `final_after_restore;attempt=...`.
- **Selected-text editing restores the passage before input.** `InsertionTarget.ExpectedSelection` travels through target reacquisition and focus changes. Immediately before native, Unicode or clipboard input, `RestoreExpectedSelectionAsync` verifies the exact passage, retries the captured range, searches a unique text occurrence, and reacquires the field when Chromium replaced its accessibility node. If the passage cannot be restored unambiguously, SonaBar refuses the edit instead of appending at a lost caret or duplicating text. `ValidateSelectionTarget` checks editability and native content fingerprints without rejecting an expired UIA range that can still be recovered.
- **Translation retries instead of silently returning the original.** If protected placeholders do not survive the first writing-model response, or if the response mostly repeats the source wording, `AppController.TranslateAsync` retries once with a strong preservation contract and then validates the protected names and numbers again. An unchanged or mostly unchanged second response is rejected with an explicit error instead of being reported as a successful translation. Real `qwen3-4b` smoke output translated a German/English sentence, French and Chinese text while preserving names, times and numbers.
- **Chromium caret focus is restored after the Start button.** Activating SonaBar can leave a browser contenteditable with accessibility focus while its DOM focus falls back to the page body. When dictation starts from SonaBar, the insertion service now clicks the stored caret (or the middle of an empty field) after restoring the window, then verifies the foreground and focus again immediately before SendInput. The Start button therefore inserts into Chrome/Claude contenteditables instead of SonaBar's own fields.
- **Browser page selections are not field selections.** Chromium can expose the page-level selection through a contenteditable's TextPattern. `SelectionFor` now requires the selected text to occur inside the field's own inspectable content, so selecting page text no longer opens the selection editor instead of starting dictation.

## Unfinished / Known Issues

- The compact-only shell, settings dialog open/cancel, **Go to** routing (20 pages), **Tray > Tools**, close-to-tray, silent second launch and real Parakeet readiness were verified on the installed 2026-10-27 build. The custom title bar, circular logo, privacy pill, pin toggle, gear, minimize, close-to-tray, rounded top corners and visible keyboard focus were verified visually and through UI Automation on the installed build; title-bar drag was verified on the debug build. High-contrast rendering, onboarding handoff, minimum-hold discard on a real key press, CPU-thread application and GPU-fallback display still need manual verification.
- The clipboard-first rich-composer path is verified in an Edge contenteditable with the Discord/Slate class `slateTextArea_ec4baf`, including the normalized `changed_assumed` case. Real OpenCode and Discord Canary still need a fresh manual run on the installed build; inspect `diagnostics.log` for `reason=composer_target`, `partial=detected`, `recovery=select_all` and `changed_assumed`. The older installed build reached Discord Canary with `sendinput_unicode;result=verified`, but that run predates the new clipboard-first path. Selected-text replacement with a slow real writing model and a focus change passed in a native WinForms TextBox (`selection=expected_verified`, `sendinput_unicode;result=verified`, `delivery=confirmed`). Edge/Chromium contenteditables, Windows 11 Notepad, OpenCode, Discord Canary, Office and the rest of the application matrix still need a live pass; inspect `selection=expected_verified`, `selection=expected_recovered_by_text` and `selection=expected_reacquired`.
- Parakeet TDT currently ignores native speech contexts without a Flashlight decoder, so custom words do not improve Parakeet accuracy. The ABI path is exercised but no boosting effect is claimed; a decoder/lexicon integration would be required to change this.
- Parakeet is batch-only and does not expose a detected language code through NeMo-Speech.cpp, so the history language remains `auto` when automatic selection is used.
- German was verified with locally synthesised speech. A dictation on a real microphone is still part of the manual checklist.
- The processor topology API reports an inconsistent layout on some Windows builds, so the application reports the logical processor count only.
- The manual device/DPI/sleep/insertion matrix still needs to run against packaged binaries and downloaded models.
- Typed snippet expansion still needs a physical-keyboard test in Notepad, a browser password field, an elevated target and a game. Injected test input is intentionally ignored by the hook.
- The Parakeet and Qwen runtime and packaging changes are part of this release candidate; no new release tag has been published for the compact-first build.
