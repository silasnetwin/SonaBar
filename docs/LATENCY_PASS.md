# Dictation latency pass — 3 October 2026

The user's local timing log showed approximately 9 seconds from recognition start (T5) to transcript (T6) for a 41-second dictation using a custom `large-v3` model. The captured target was `ChatGPT.exe` with a generic UI Automation pane; SineFlow refused to claim insertion when focus could not be verified.

Changes: start speech-model loading while recording; make CPU the default speech backend for `Automatic`; retain explicit GPU selection; attempt an OS-caret-based edit-provider lookup when UI Automation reports a generic pane; and require a measurable increase in inserted text occurrences before confirming clipboard or Unicode delivery. The original HWND/process and focus guards remain.

Local CPU measurements on bundled reference audio (`small` Whisper, English): 11-second clip, 574 ms cold load + 3,136 ms warm recognition; 4-second clip, 324 ms cold load + 2,856 ms warm recognition. The same 4-second clip with Vulkan took 791 ms + 14,874 ms. The installed custom `large-v3` model took 3,080 ms + 15,962 ms on CPU. `base` took 166 ms + 825 ms on CPU. These are recognition-only samples, not stop-to-insert or German accuracy benchmarks; benchmark runs varied slightly. Greedy decoding improved the 4-second `small` run to 2,598 ms, too little to justify changing the quality setting from beam search based on this sample.

For the user's near-two-second goal, `Fast` (`base`) is the measured low-latency profile on this machine. It trades recognition accuracy for speed. The installed app was updated from the packaged Release build, and the user's active profile was changed to `Fast`. The previous `large-v3` custom model remains recorded in settings; a timestamped settings backup and application backup were retained. The installed-app isolated smoke test passed (tray, settings, 10 catalog models, four detected microphones, idle state). All 104 automated tests, Release build and analyzer verification passed. Real microphone, ChatGPT composer, Chromium/Office, and other target-field insertion need live interaction testing; no perfect-insertion claim is made.
